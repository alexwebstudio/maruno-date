# Восстановление пароля — настройка и проверка

Маршруты: `/auth/forgot` (запрос) и `/auth/reset` (создание нового пароля).
Собственных «временных паролей» проект не выдаёт — используется штатный
механизм Supabase Auth.

---

## Как это работает

1. Пользователь вводит почту на `/auth/forgot`.
2. Вызывается `supabase.auth.resetPasswordForEmail(email, { redirectTo: <origin>/auth/reset })`.
3. Supabase отправляет письмо. В зависимости от шаблона в письме будет **ссылка**,
   **код** или и то, и другое.
4. Подтверждение владения почтой:
   - по ссылке — Supabase поднимает сессию восстановления и открывает `/auth/reset`;
   - по коду — `supabase.auth.verifyOtp({ email, token, type: 'recovery' })` на `/auth/forgot`,
     после чего пользователь переходит на `/auth/reset`.
5. На `/auth/reset` вызывается `supabase.auth.updateUser({ password })`, затем
   `signOut()` — временная сессия закрывается, войти нужно уже новым паролем.

Страница `/auth/reset` показывает форму **только при активной сессии
восстановления**. Без неё выводится «Ссылка недействительна» и предложение
запросить письмо заново.

---

## Что настроить в Supabase

### 1. Redirect URLs

**Authentication → URL Configuration → Redirect URLs** — добавить:

```
http://localhost:3000/auth/reset
https://date.maruno.kz/auth/reset
```

Без этого переход по ссылке из письма завершится ошибкой.

**Site URL** — боевой адрес: `https://date.maruno.kz`.

### 2. Шаблон письма (нужен для кода)

**Authentication → Email Templates → Reset Password.**

По умолчанию в шаблоне только ссылка `{{ .ConfirmationURL }}`. Чтобы работал
ещё и ввод кода, добавьте в письмо `{{ .Token }}`:

```html
<h2>Восстановление доступа к Maruno</h2>
<p>Нажмите кнопку, чтобы задать новый пароль:</p>
<p><a href="{{ .ConfirmationURL }}">Задать новый пароль</a></p>
<p>Или введите код на сайте: <strong>{{ .Token }}</strong></p>
<p>Если вы не запрашивали восстановление — просто проигнорируйте письмо.</p>
```

Если оставить шаблон по умолчанию, поле ввода кода останется на экране,
но пользователю достаточно перейти по ссылке — интерфейс об этом прямо пишет.

### 3. Срок жизни и частота запросов

**Authentication → Providers → Email:**

- *Email OTP Expiration* — срок действия кода и ссылки. Рекомендую **3600 секунд** (1 час).
- Ограничение частоты писем задаётся в **Authentication → Rate Limits**.
  Значение по умолчанию (несколько писем в час на адрес) подходит.

На стороне интерфейса дополнительно стоит таймер: повторная отправка доступна
через 60 секунд.

---

## Что сделано для безопасности

| Требование | Как реализовано |
|---|---|
| Срок жизни кода и ссылки | Настройка Supabase, по умолчанию 1 час |
| Ограничение частоты | Rate limits Supabase + таймер 60 с в интерфейсе |
| Не раскрывать существование аккаунта | Текст «Если аккаунт с такой почтой существует…» одинаков в любом случае; ошибка отправки не показывается |
| Защита от перебора кода | Проверка на стороне Supabase, попытки ограничены его rate limits |
| Отзыв использованного токена | После смены пароля вызывается `signOut()`, токен восстановления одноразовый |
| Просроченный код | Отдельное сообщение «Срок действия истёк — запросите новый» |
| Надёжность пароля | `lib/password.ts`: минимум 8 символов, буква и цифра, отказ на частых паролях |
| Повтор пароля | Отдельное поле со сверкой и понятной ошибкой |

## Как проверить

1. `/auth/login` → «Забыли пароль?».
2. Ввести почту существующего аккаунта → «Отправить письмо».
3. Экран подтверждения: таймер повторной отправки идёт от 60.
4. Открыть письмо:
   - перейти по ссылке → откроется `/auth/reset` с формой;
   - либо ввести код из письма на `/auth/forgot`.
5. Задать новый пароль: индикатор надёжности реагирует, при несовпадении полей
   кнопка заблокирована.
6. После сохранения — экран «Пароль изменён», вход старым паролем больше не работает.

**Проверка граничных случаев:**

- Открыть `/auth/reset` напрямую без письма → «Ссылка недействительна».
- Использовать ссылку дважды → то же сообщение.
- Ввести неверный код → «Код неверный. Проверьте последнее письмо».
- Ввести почту, которой нет в базе → тот же экран подтверждения (существование
  аккаунта не раскрывается).

---

## Смена пароля из кабинета

Отдельный сценарий: **Настройки → Аккаунт → Смена пароля**.
Требуется текущий пароль — он проверяется повторным `signInWithPassword`
перед вызовом `updateUser`. Без этого сменить пароль нельзя, даже если
устройство осталось незаблокированным.
